# v2.0 upstream-first 迁移说明

## 默认变化

- 该迁移文档对应 v2.0；当前技能版本为 `2.2.0`。
- 新项目和新连续剧默认安装档位为 `upstream-dialogue`。
- 新项目默认 `audio.mode=native-dialogue`、`audio.generate_audio=true`、`audio.subtitle_source=none`。
- QuickAI 仍是默认视频上游；用户说“生视频选择 QuickAI New”时写入 `video_provider=quickainew`、`video_provider_policy=fixed`，T2V/I2V 都直连 QuickAI New。
- QuickAI 的原生音频是模型默认能力，QuickAI New 使用显式 `generate_audio` 字段；两者当前都不支持视频参考/编辑/延展或音频参考。

## 旧项目

旧 `project.json` 保留 `version=1` 以避免破坏状态和路径。缺少 `audio.subtitle_source` 的旧项目仍按 `project` 兼容，以免旧的本地字幕流程消失；新建项目才默认 `none`。旧项目的 `preserve`、`local-voice` 和 `local-lipsync` 不会被自动改写。

旧项目中的 `limits.max_prompt_chars` 作为迁移别名读取，但 v2 实际按 UTF-8 字节计算。建议预检后改为 `limits.max_prompt_bytes`，并缩短到 3800 字节工作上限。

## 提示词迁移

每个角色母版、图片和视频请求都保留完整、精简、最小三个版本。预检显示 Unicode 字符数、UTF-8 字节数、剩余空间和压缩建议；生成时只会发送完整版本或一个完整的压缩版本，不会静默截断。最小版本仍超过 4096 字节时，必须缩短角色身份、地点、动作、对白或结束姿态。

## 重试迁移

默认 `retry_policy.max_total_attempts=3`、`max_retries=2`。总次数包含自动备用上游；需要三次重试时显式设置四次总尝试。`submission_unknown` 不自动重新创建，已有任务 ID 只恢复轮询和下载。每次尝试都会写入请求 ID、尝试 ID、任务 ID、上游、错误分类和提示词版本。

拒绝图片会归档到 `assets/rejected/`，拒绝视频会归档到 `clips/rejected/`。归档文件名包含镜头 ID 和 SHA-256；替换生成写入新的标准文件，不覆盖被拒绝的媒体。

## 连续剧迁移

`series.json` 新增 `contract_version=2.0`、季主题、冲突升级、中点、高潮和结尾钩子字段，并在镜头中使用 `shot_role`。建议两分钟单集规划 12-18 个 1-15 秒镜头，覆盖 establishing、动作、反应、非对白视觉和 ending_hook。下一集只继承上一集实际验收后的 `continuity_summary`。

## 安装与回滚

升级前检查仓库是否位于 `main`，工作区不干净时只报告。使用 `install.ps1 -Repair -Force` 或 Codex-managed 安装会保留 DPAPI 凭据、项目、角色母版、第三方源码和模型缓存，不要求重新输入 Key。基础安装不会下载或启动 CosyVoice、MuseTalk、Voicebox、VoxCPM 或 Docker 模型。
