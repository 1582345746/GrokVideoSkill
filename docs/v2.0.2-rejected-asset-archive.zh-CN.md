# v2.0.2 拒绝素材归档修复（历史）

> 当前版本为 v2.1.0；本页只记录拒绝素材归档的历史兼容行为。

## 问题

`review-shot --decision reject` 会在状态中保留审核结果、SHA-256 和任务历史，但替换生成仍写入同一个标准文件名，导致被拒绝的图片或视频媒体被新版本覆盖。这与技能文档承诺的“拒绝素材保留”不一致。

## 修复

- 拒绝图片时，原文件移动到 `assets/rejected/`。
- 拒绝视频时，原文件移动到 `clips/rejected/`。
- 归档文件名包含镜头 ID 和完整 SHA-256，可审计且不会与新标准文件冲突。
- `state.json`、审核返回值和事件日志记录归档后的项目相对路径。
- 替换生成继续写入原标准位置，已拒绝媒体不再被覆盖。

该修复不创建上游任务，不改变凭据、项目版本或已有任务恢复规则。替换生成仍必须显式提供 `--retry-failed` 和 `--retry-reason`，并受项目总尝试次数限制。
