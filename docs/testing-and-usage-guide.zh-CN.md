## 1. 测试原则

### 费用等级

| 标记 | 含义 | 典型操作 |
| --- | --- | --- |
| A | 不创建上游生成任务 | 安装、`version`、`capabilities`、预检、状态、FFmpeg、QA |
| B | 访问上游但不创建媒体 | `doctor`、模型发现、任务轮询、已有结果下载 |
| C | 可能产生上游费用 | 生图、文生视频、图生视频、明确重试失败任务 |
| D | 本地 GPU 计算 | CosyVoice、MuseTalk；不产生 QuickAI 媒体生成请求 |

每个 C 级测试都应先让 Codex 展示：项目目录、模式、提供方、镜头数、每镜头时长、生图请求数、生视频请求数、提示词长度和预算。未得到明确批准前只能创建项目、写剧本和预检。

测试项目使用独立目录，不能覆盖先前成片。保留 `project.json`、`state.json`、原始镜头、`deliverables/final.mp4` 和 QA 报告。遇到创建请求超时且没有任务 ID 时，不允许自动创建第二个付费任务。

建议按以下顺序验收：升级安装、基础诊断、短文生视频、用户图片图生视频、角色母版、原生对白、字幕、精确配音、口型、三集迷你连续剧、短新闻、后期、恢复和最终 QA。

## 2. 已安装旧版机器的升级验收

费用等级：A/B。

标准话术：

```text
请把这台机器已经安装过的 Grok Video Studio 更新到仓库 main 分支最新版：
仓库：https://github.com/1582345746/GrokVideoSkill.git

先检查现有仓库和安装目录。工作区干净时使用 fast-forward 拉取 main；如果有未提交修改，先报告，不要覆盖。然后运行 install.ps1 -Repair -Force。

保留已有 DPAPI 凭据、安装档位、项目、组件源码和模型，不要重新要求输入 Key，不要重新下载已有模型。完成后运行 version、install.ps1 -Check、doctor 和 capabilities。允许读取上游模型列表，但不要创建任何付费图片或视频任务。
```

通过标准：

- 安装版本为 `1.8.0`。
- 安装目录可读取，`install-plan --profile basic` 成功。
- 既有凭据角色仍可用，输出中没有 Key 或 Key 片段。
- FFmpeg 和 ffprobe 可用。
- 既有项目、模型目录和 DPAPI 文件没有被删除。
- 默认安装不会启动 CosyVoice 或 MuseTalk。

## 3. 基础诊断

费用等级：A/B。

```text
使用 $grok-video-studio 做一次只读诊断。运行 version、capabilities、install-plan --profile basic 和 doctor；列出四条产品路线、当前安装档位、已配置的凭据职责、FFmpeg 状态和可选本地组件状态。不要输出任何 Key，不要创建项目，不要发起生图或生视频请求。
```

通过标准：

- 能区分 QuickAI 生图、QuickAI 主视频和 QuickAI New 备用视频三个职责。
- 四条产品路线为文生视频、图生视频、连续剧、新闻视频。
- 用户图片动画被归入图生视频。
- 缺少当前测试不需要的 Key 只能作为提示，不能阻断其他模块。

## 4. 文生视频

费用等级：C。建议首次只做 1 个 6 秒镜头。

```text
使用 $grok-video-studio 创建一个 6 秒、9:16、480p 的文生视频测试：清晨的乡村公交站，一名背双肩包的原创年轻人登上进城公交，镜头缓慢跟拍，写实电影感。

使用 text-to-video 和 QuickAI 文生视频，不要生图，不要创建角色母版。画面禁止字幕、文字、点赞、评论、弹幕、按钮、Logo、水印和贴纸。先展示最终提示词、字符数、1 次视频请求和预算，等我明确回复“批准生成”后再调用上游。完成后运行 QA 并打开首帧、末帧供人工检查。
```

通过标准：

- 预检报告为 0 次生图、1 次生视频。
- 视频方向为竖屏，时长大于 0，可播放并能被 ffprobe 读取。
- 没有意外界面元素、字幕或水印。
- 有无音轨被如实报告；不能把 `has_audio=true` 写成“已经有人声”。
- `state.json` 保存任务 ID 和下载结果。

## 5. 用户图片图生视频

费用等级：C。只需要图生视频请求，不应重新生图。

```text
使用 $grok-video-studio 把这张现成图片制作成 6 秒 9:16 图生视频：<图片绝对路径>。

使用 image-to-video 和 single-image-animation。不要调用生图接口，不要改变人物身份、脸型、服装、构图和背景；只增加自然眨眼、呼吸、发丝轻动和很小幅度转头。先把图片复制到项目 assets/references，展示预检和 1 次主视频请求，等我批准后再优先调用 QuickAI；只有安全分类的失败才允许自动切换 QuickAI New。完成后检查最终提供方、尝试历史、首末帧人物一致性和画面形变。
```

通过标准：

- 预检为 0 次生图、1 次图生视频。
- 项目只引用相对路径，不把外部绝对路径写入项目合同。
- 发给视频上游的是用户图片，不是无关的旧关键帧。
- 主体身份、服装、背景和构图没有明显漂移。

## 6. 角色母版与关键帧图生视频

费用等级：C。会产生生图和图生视频请求。

```text
使用 $grok-video-studio 做一个两镜头、每镜头 5 秒的角色一致性测试。角色是一名 24 岁原创中国农村青年，短黑发、深绿色夹克、旧帆布双肩包。先生成一张包含同一人物正面、侧面和全身视图的单张角色母版，再为“公交站”和“城市招聘会”分别派生镜头关键帧，最后优先使用 QuickAI 做图生视频，安全失败时才使用 QuickAI New。

先展示角色设定、母版提示词、两个关键帧提示词、生图/视频请求数和预算，不要立即生成。每个视频请求只能发送当前镜头关键帧，不能把三视图母版直接发给视频模型。等我逐阶段批准：先母版，再关键帧，再视频。
```

通过标准：

- 只有一张多视角母版，不是三张互相漂移的人像。
- 两张关键帧都能追溯到同一母版。
- 每个视频请求只携带当前镜头关键帧。
- 两个镜头中的脸型、发型、服装主色和背包一致。
- 若仍有明显身份漂移，必须如实标记，不能只凭技术 QA 判定通过。

## 7. 上游原生对白

费用等级：C。无需 CosyVoice 或 MuseTalk。

```text
使用 $grok-video-studio 做一个 8 秒文生视频，让一名原创 AI 主持人面对镜头说：“你好，这是今天的重点消息。”使用 upstream-dialogue 档位和 native-dialogue。

先展示对白文本、说话时间窗、generate_audio 设置、最终视频提示词、请求数和预算，等我批准后生成。完成后必须实际播放并检查：是否有可听人声、逐字内容是否正确、口型是否自然、画面是否被上游自动烧入字幕。不要因为存在音轨就宣称对白成功。
```

通过标准：

- 请求启用了上游音频生成。
- QA 报告平均/峰值音量和静音占比。
- 人工听审记录实际听到的文本，而不是复制剧本文本。
- 人工记录口型和意外内嵌字幕情况。
- 若逐字、声音或字幕不合格，建议切换精确配音或干净母版，不虚报稳定性。

## 8. 精确字幕

费用等级：A。复用已有成片，不应重新生成视频。

```text
使用 $grok-video-studio 为当前项目生成确定性 SRT。字幕文本必须来自已批准的对白、旁白或字幕时间轴，使用 subtitle_source=project。先导出 SRT 给我检查，不要立即烧录。

我确认文字和时间轴后，分别说明 clean、cinematic、news 三种样式，再按我选择的样式用 FFmpeg 输出 final-subtitled.mp4。始终保留 final.mp4。若源视频来自 native-dialogue，先逐镜头确认没有上游内嵌字幕，只有确认干净后才允许烧录，避免双层字幕。
```

通过标准：

- `deliverables/subtitles.srt` 可读，序号和时间范围合法。
- 文本与批准剧本一致，时间窗不重叠且不超出视频。
- 烧录只产生衍生视频，不覆盖干净母版。
- 改样式不产生新的 QuickAI 请求。
- 不能把该功能描述为“自动识别任意视频里的语音”；当前精确字幕来源是项目合同。

## 9. CosyVoice 精确配音

费用等级：D。需要 `precise-voice`，但可复用现有干净视频，避免新的 QuickAI 请求。

```text
使用 $grok-video-studio 对当前项目做 CosyVoice 精确中文配音。先运行 install-plan --profile precise-voice 和 components-doctor，只报告现有 Docker、NVIDIA、CosyVoice 源码、模型和服务状态；缺失时先展示下载量与磁盘位置，未经我批准不要安装。

使用已批准对白：“第一次来这座城市，我会认真把路走下去。”对白文字同时作为字幕唯一来源。声音只能使用 synthetic、owned 或 licensed 素材，并核对 reference_text。先启动 CosyVoice，再生成逐句 WAV、dialogue-track.wav、对白混音版和 SRT；保留 final.mp4。完成后报告实际时长、响度、静音占比和缓存状态，然后停止服务。
```

通过标准：

- `dialogue-state.json` 和逐句 WAV 可恢复。
- 生成文本与批准文本逐字一致。
- 对白位于声明时间窗内，源音频在对白期间被正确压低。
- 输出对白版和字幕文件，不覆盖干净母版。
- 重复执行相同对白时复用缓存，不重复合成。
- 没有合法声音授权和准确参考文本时必须停止。

## 10. MuseTalk 口型同步

费用等级：D。需要 `lip-sync`；8 GB 显卡应分阶段运行服务。

```text
使用 $grok-video-studio 对已经完成 CosyVoice 配音的原创 AI 人物视频做 MuseTalk 口型同步。先运行 install-plan --profile lip-sync 和 components-doctor，展示模型、磁盘、Docker、GPU 与端口状态，未经批准不要下载。

这台机器显存为 8 GB 时必须分阶段：先只启动 CosyVoice 完成并缓存对白，停止或切换后只启动 MuseTalk，复用缓存音频执行 local-lipsync。不得同时启动两个服务。输出独立口型版，保留干净母版和普通对白版；完成后导出人脸近景审阅帧并停止服务。
```

通过标准：

- 服务只监听 `127.0.0.1`。
- 8 GB GPU 下没有同时运行 CosyVoice 和 MuseTalk。
- 第二阶段复用对白缓存，没有重新生成语音。
- 嘴部运动与语音节奏大体一致，没有严重脸部扭曲、闪烁或身份变化。
- 技术成功但视觉不自然时仍判人工验收失败。

## 11. 连续剧

费用等级：规划为 A；角色母版和每集生成是 C。验收时建议先做 3 集、每集 20-30 秒的迷你系列，不要直接付费生成 20 集。

### 规划测试

```text
使用 $grok-video-studio 创建一部 3 集连续短剧测试，每集 24 秒，图生视频路线。主题是农村青年第一次进城求职。先创建 series.json 和三集项目，写整季剧情弧线、固定角色、服装、地点、道具、每集开头状态、剧情、结尾状态和全部分镜提示词。不要生图或生视频。完成后给我文件路径和逐集请求预算，等待我审核。
```

### 第一集生成

```text
读取刚才的系列项目。先运行 series-validate、第一集 series-context 和 series-preflight，把角色母版、第一集分镜、请求数和预算给我。只有我回复“批准第一集”后才 series-approve 并生成 ep-001。生成后停在 needs_review，打开成片和全部审阅帧，不要自动接受，也不要生成第二集。
```

### 验收与下一集

```text
我已看完第一集。根据成片实际画面记录人物服装、所处位置、手中道具、情绪和最后动作；不要照抄原计划。运行 series-accept 保存 continuity-summary。然后执行 series-next 和 series-context，展示第二集如何承接实际结尾，预检后等待我批准，不要自动生成。
```

通过标准：

- 未批准的集数不能生成。
- 前一集未人工接受时，后一集审批被阻止。
- 每集生成后停在 `needs_review`。
- 连续性摘要描述实际成片结尾，而不是计划结尾。
- “生成下一集”只处理一集，不批量消耗整季预算。

## 12. 新闻视频

费用等级：研究和验证为 A；生图/视频为 C。

```text
使用 $grok-video-studio 创建一个最近 24 小时热点新闻视频测试，目标 24 秒。你必须联网查找当前来源，优先使用官方或第一手页面，并至少加入两个不同发布者。先创建 news.json，列出检索词、链接、发布和访问时间、来源类型、逐条事实主张、冲突项、旁白及每个镜头对应的 claim_id。

不得把没有画面授权的新闻图片下载进项目；visual_rights=facts-only 时只生成原创示意画面。先运行 news-validate，把证据合同和视频预检给我，不要生成。我批准后才调用上游。成片中明确标示 AI 示意，不得冒充现场素材。
```

通过标准：

- 使用当前网页而不是模型记忆。
- 至少两个独立发布者，关键主张有第一手来源或双来源支持。
- 来源冲突已解决或在脚本中明确保留不确定性。
- 每段旁白和镜头能追溯到 `claim_id`。
- 未通过 `news-validate` 时生成被阻止。
- AI 重建画面没有被描述为真实新闻现场。

## 13. 拼接、后期和封面

费用等级：A。

### 现有视频拼接

```text
使用 $grok-video-studio 按我给出的顺序拼接这些 MP4：<视频路径列表>。先用 ffprobe 报告每段的时长、尺寸、帧率和音轨；统一为 H.264、yuv420p、30 fps，target-size=auto，audio-policy=preserve。输出新文件，不修改原片。完成后报告总时长和音视频流。
```

### 轻量后期

```text
使用 $grok-video-studio 对 <输入视频> 做轻量后期：添加 <音乐路径>、<旁白路径>、<SRT 路径> 和 0.5 秒淡入淡出。先检查素材存在和授权，压低背景音乐避免遮住人声，输出到新文件并运行媒体 QA。不要调用上游生成接口。
```

### 封面

```text
使用 $grok-video-studio 从 <输入视频> 的 0.5 秒位置导出 PNG 封面。先确认该帧不是黑帧、转场或明显人物畸变；不合格时从审阅帧中选择更清晰的一帧。不要修改视频。
```

通过标准：原文件保留；输出可播放；拼接顺序、时长和音频策略符合要求；没有因为某一段无音轨而丢掉其他段的音频。

## 14. 断点恢复与失败重试

费用等级：A/B；只有明确重新创建失败任务时为 C。

```text
使用 $grok-video-studio 检查 <项目目录> 的 state.json 和 status。列出每个镜头的本地状态、上游 task_id、已下载文件和未完成步骤。已有 task_id 的任务只允许 resume、轮询或下载，不能创建第二个任务。

如果创建请求失败且没有 task_id，把它标记为 ambiguous 并停止，说明重复计费风险。只有我明确批准并给出重试原因后，才能使用 --retry-failed --retry-reason "<原因>" 创建新任务。恢复完成后再 assemble 和 qa。
```

通过标准：

- 已有任务 ID 不重复创建。
- 重试原因进入历史状态。
- 部分镜头运行不会错误地自动拼接不完整成片。
- `state.json` 中不含密钥。

## 15. 最终 QA 与测试记录模板

### 标准 QA 话术

```text
使用 $grok-video-studio 对 <项目目录> 运行严格 QA。报告容器、编码、分辨率、方向、帧率、时长、音轨、平均/峰值音量、静音占比、黑帧和冻结风险。打开每个镜头的首帧和末帧进行人工检查，逐项记录人物一致性、肢体、运动、口型、字幕、Logo、水印和意外短视频界面元素。技术检查通过不能替代人工通过；发现问题时指出具体镜头和建议处理方式。
```

### 单模块记录模板

```text
模块：
测试日期：
技能版本：
项目目录：
安装档位：
提供方与模式：
计划请求数：
实际创建请求数：
是否发生重试：
输出文件：
技术 QA：通过 / 不通过
人工画面 QA：通过 / 不通过
人工听审：通过 / 不通过 / 不适用
发现问题：
处理决定：接受 / 重烧字幕 / 本地修复 / 重生成指定镜头 / 停止
```

### 全模块通过条件

| 模块 | 自动检查 | 必须人工检查 |
| --- | --- | --- |
| 安装与诊断 | 版本、凭据角色、FFmpeg、无密钥泄漏 | 无 |
| 文生视频 | 请求、MP4、时长、方向、状态 | 内容、人物、UI、水印 |
| 图生视频 | 引用图、MP4、状态 | 身份、构图、形变、运动 |
| 上游对白 | 音量和静音比 | 逐字、声音、口型、内嵌字幕 |
| 精确字幕 | SRT 格式、时间窗、衍生文件 | 文案、断句、遮挡、安全区 |
| 精确配音 | 缓存、时长、响度、混音 | 音色、语气、授权、自然度 |
| 口型同步 | 服务、输出、人脸审阅帧 | 嘴部同步、闪烁、脸部畸变 |
| 连续剧 | 审批状态、顺序、连续性文件 | 实际结尾、跨集身份和道具 |
| 新闻 | 来源和 claim 映射 | 事实表述、示意标记、语气 |
| 后期 | 编码、时长、音轨 | 节奏、混音、字幕和封面 |

只有自动检查与相应人工检查都通过，才能把模块标记为“满足用户使用”。

## 16. 内部创意预设快速话术

下面这些是标准文生视频或图生视频项目的内部预设，不是新的产品路线。它们同样遵循“先剧本与预检、后批准、再付费生成”的门禁。

### 通用视频项目

```text
使用 $grok-video-studio 创建一个通用视频项目。先根据我的目标说明文生视频和图生视频两种路线的成本、人物一致性和参考图差异，让我选择；再给出分镜、提示词和预检，不要直接生成。目标：<目标描述>。
```

### 单集人物短剧

```text
使用 $grok-video-studio 的 short-drama 预设做一个 30 秒单集人物短剧，不要创建连续剧项目。先写人物身份锁、剧情起承转合、每镜头动作和连续性说明；严格人物一致性时使用角色母版和逐镜头关键帧。展示生图/视频请求数和预算，等我批准后逐阶段生成。
```

### 产品广告

```text
使用 $grok-video-studio 的 product-ad 预设，把这张产品图制作成 15 秒广告：<产品图路径>。保持产品外形、商标位置、包装文字和颜色不变，先规划特写、旋转展示和使用场景。不要让模型重新绘制包装文字；先预检并等我批准，再用图生视频生成，完成后逐镜头核对产品一致性。
```

### 人物跳舞与表演

```text
使用 $grok-video-studio 的 dance-performance 预设，把这张原创或已获授权的人物图制作成 8 秒全身舞蹈视频：<人物图路径>。保持脸、发型和服装不变，动作幅度与画面构图匹配，避免手脚出框和肢体畸形。先预检，批准后只做一次图生视频，完成后检查首末帧和四肢动作。
```

### 搞笑动作视频

```text
使用 $grok-video-studio 的 comedy-action 预设，把这张主体图片制作成 6 秒轻喜剧反应视频：<图片路径>。笑点通过表情、停顿和小幅动作完成，不添加短视频点赞、评论、弹幕或贴纸。先展示动作节拍和预检，等我批准后生成。
```

### 插画、建筑与风景动效

```text
使用 $grok-video-studio 的 scene-animation 预设，让这张插画或风景图自然动起来：<图片路径>。保持主体构图和美术风格，只让云、水面、树叶、光影或景深产生分层运动，禁止整体画面漂移和新增人物。先预检，批准后生成 8 秒图生视频。
```

这些预设的验收重点不同：产品广告检查产品和文字，舞蹈与搞笑动作检查肢体，场景动效检查构图漂移，人物短剧检查跨镜头身份与叙事连续性。
