# 2026-10-08：案例对比、架构审查与最新开发清单

## 结论与适用范围

需要重构创作与审核层，保留已经有效的上游接入、凭据、付费请求账本、任务恢复与 FFmpeg 工具。当前失败来自剧本语义、镜头组织、提示词实际编译和成片审核共同失效；继续增加题材预设或给每镜追加“快一点、不要叹气”不能解决。

本次以用户提供的约218秒供货冲突案例录屏，与 projects 内68个项目配置、11个交付MP4、9个独立故事做比较。案例录屏以前三集为主体，末尾有下一集开头；不把录屏总时长当成单集时长。主要比较一号宿舍对白版、宿舍旁白版、惊悚系列第一集和“最后电池”。案例分析基于候选切点帧、分段接触表、中文OCR和音量测量；没有完成本工具环境中的人耳听审，也不知道作者所用模型、配音方法或失败素材数量。

这份清单是产品路线图；“已实现”只表示相应代码和约束已落地，不表示生成画面一定合格。生成样片、实际对白听审、用户满意度分别记录，不能从测试通过推断视频好看。

## 已证实的代码根因

基线为审查前的 2.7.0 / commit `5160fbb`，文件为 `scripts/grok_video_studio.py`、`director_contracts.py`、`dialogue_workflow.py` 和 `media_tools.py`。

1. `story_clarity_score` 只给字段非空计分，两个 `max()`还能掩盖缺失层。把全部因果文本替换为同一个“不相关”，仍能得到100。它只能叫结构填写率。
2. 原生对白编译丢弃`start/end`，却要求“优先停顿，不赶进固定时点”。慢节奏写在生产契约里。
3. 宿舍全部16镜实际使用compact；full提示词约5.6–6.4KB超限，compact丢掉场景/道具状态、发言焦点、因果字段及框架的防叹气保护。写在full里不等于真实发给了模型。
4. 空`character_ids`在compact被解释为全体角色；母版和单镜生图接收全局角色表与自由风格故事，产生群像污染。整集结局也进入当前镜头请求。
5. strict director禁止100%对白覆盖，审查还提示增加无对白镜头，强行制造空段。听者反应与对白可以共存。
6. “上一镜衔接”用的是上一镜开场图，不是视频剪辑出点。生成视频前还未强制核验实际参考图批准及hash。
7. 尾部差分只测像素运动，叹气、点头、挥手都可能通过；背景运动也能掩盖人物停住。
8. QA叙事结论来自计划，视觉批准没有再次校验文件，原生对白`audio_pass`一直null且无听审回写路径；无Tesseract时清洁画面也无法通过有效人工记录闭环。

首轮真实生成还确认一个独立问题：完整`scene_state/asset_state`会让模型在脸部近景里重新生成画外货车和货筐；同一场景参考图又会把初始盖布与全体人物带回后续动作镜头。2.8新增可选`prompt_state.scene/assets`作为当前可见状态投影，完整世界状态仍保留作连续性检查。`location/props/keyframe_description`也必须与投影一致，不能从另一字段重新注入隐藏物件。局部动作参考不等于每镜复制整场初始布局。

原生模型还有真实限制：它不能保证逐字对白、发言人、口型和物体接触关系。框架必须降低复杂度、审核和局部修复；提示词不能成为保证书。案例作者的具体工具链未知，不能据画面断言他们使用了哪种模型或后期配音。

## 目标架构

```text
需求与参考证据
    ↓
Event：一件事、主角目标、对立目的、期限/代价
    ↓
Beat：触发→选择→可见或可听结果→下一步依赖
    ↓
Coverage：发言人 / 听者 / 动作 / 物件，声音可跨画面
    ↓
Asset：角色母版、场景母版、道具及实体状态
    ↓
Generation clip：一次付费生成，局部作用域、可恢复任务
    ↓
Edit shot：素材窗口、声画桥接、对白落点和动作切点
    ↓
实际像素/对白/连续性审核 → 局部修复 → 最终理解测试
    ↓
审核通过的正式交付 / 明确标注待审的验证片
```

事件拍点与编辑镜头不能一一绑定。一次威胁可以切三个画面，而不产生三个新事件；一个反应镜头也不能重新解释整集。2.8首轮以`event.mode=advance|coverage`区分推进与同拍点覆盖，保留现有项目格式兼容；独立clip/edit多对多模型列入后续开发。

Codex负责原本就擅长的剧本、因果推理、空间拆镜、像素阅读和修复决策；脚本负责可重复的校验、计费、hash、调用、剪辑和审查账本。不要用一个巨大提示词替代两层职责。

## 制作验证片的验收与停止条件

本轮验证选原创《最后一车菜：先验货再付钱》，约60秒、三核心人物、一个收货地点、26个编辑镜头，正常人物对白、无旁白、无字幕。模仿的是“索取→拒绝→新手段→验证→筹码失效→可见结果”的因果组织与短交锋，台词和人物独立创作。

先检查剧本可懂和价格/权限/验货动机，再生成角色母版与关键帧并审核，最后才生成视频。若角色母版污染、画面人物与台词不符或连续状态不成立，先修对应资源，不能带着缺陷继续收费。

最终按以下实际内容判定，不以预检分代替：

- 前6秒能听/看清原价三块、当前一块和赶车目标；每个回答紧接问题。
- 品质质疑有实际检查证据；车权和买方价格的揭示来自司机。
- 先完成原价成交，再追问其他农户；不能只争吵一分钟毫无结果。
- 发言人和台词一一对应；重要数字、否定词和问句听得懂。
- 反打视线与道具位置合理；接触动作不穿模；背景嘴闭合。
- 不出现长无任务空段、不剪词、不在每镜末叹气/回正/告别。
- 无模型字幕、录屏UI、黑边或被隐瞒的低分辨率放大。

结构校验只能阻断可确定的问题。若本工具环境无法听审对白，该层保留待审，成片作为验证片供用户观看，不能称正式质量验收通过。若验证仍失败，记录具体坏镜头和原因，先完成局部修复；不要立即扩展到20集。
