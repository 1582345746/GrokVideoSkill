# v2.3.0 evidence-editor 发布说明

v2.3 把 v2.2 的“文本初筛 + 手动视觉类型”升级为可审计的像素证据链，并把原生 FFmpeg 编辑计划升级为 v2。两项能力适用于 T2V、I2V、连续剧、新闻视频和用户现成素材，不增加新的付费上游，也不复制个人数据库到 Skill。

## 像素证据链

标准流程分成四步：

1. `visual-evidence <project> <media...> --frames 5`：图片输出一张归一化证据帧，视频输出 1-9 张均匀分布的内部时间点帧。
2. Codex 多模态或人工审核者打开每一张返回帧，分别判断 `medium`、`subject`、`subject_nature`、`realism` 和置信度。
3. `visual-review-record <manifest> ... --frame-evidence FRAME=OBSERVATION --confirm`：保存审核者、逐帧观察、身份来源、限制和结论。
4. `visual-review-apply <project> <manifest> <receipt> --confirm`：仅应用已接受且哈希完整的回执。

源文件、证据帧、采样规则和 manifest 均使用 SHA-256 绑定。证据帧被修改、manifest 被修改、回执仍为 pending、缺少显式确认或字段不合法时均阻断应用。相同源文件与相同采样计划会恢复已有证据；重新审核会把旧回执移入 `review-history/`。

`real-person` 不能由像素外观单独推导。只有 `identity_origin=captured-real-person`、来源已确认且提供非空说明时才允许该值。AI 生成但采用真人镜头语言的人物使用 `synthetic-human`；动漫、三渲二和 CG 中接近真人的角色使用 `human-like-fictional`，即使 `medium=photoreal`、`realism=high` 也不改变其虚构来源。

## 外部视觉基准

`visual-benchmark-build` 按相对路径哈希稳定抽样，只把派生证据写入指定验收目录，不把源图片或视频复制到 Skill。`visual-benchmark-score` 校验每个审核回执并输出弱标签一致性报告。

目录名只作为宽松约束：

| 弱标签 | 允许结论 | 禁止推断 |
| --- | --- | --- |
| `动漫` | 2D/3D anime、stylized-3D 或近真人 photoreal；主体通常为 `human-like-fictional` | 因为脸像真人就写成 `real-person` |
| `动画` | 人形角色、非人吉祥物、物体或动态图形 | 把大类目录当作唯一 medium |
| `真人` | photoreal/hybrid；来源可为 `synthetic-human`、已证实 `real-person`、mixed 或 unknown | 目录名替代实际人物来源证明 |

## 编辑计划 v2

除全局滤镜和全局转场外，v2 支持：

- `--shot-filter SHOT=PRESET`：为单个输入指定滤镜。
- `--shot-speed SHOT=RATE`：0.25-4.0 倍速度，视频 PTS、音频 atempo、有效时长和转场验证同步更新。
- `--boundary AFTER_SHOT=TYPE:SECONDS`：每个边界独立选择 hard cut、dissolve、fade-black、wipe-left 或 slide-left；同一时间线可混合硬切和转场。
- `--normalize-lufs TARGET`：-24 到 -10 LUFS；也可用 `--no-normalize` 明确保留源响度。
- `preview_evidence`：输出开始、转场中心和结束证据帧，最多 9 张，每张保存 SHA-256。

连续硬切片段先确定性编组，再在组之间执行 FFmpeg `xfade`，避免不同滤镜输出时间基不一致。输入或计划签名不变时，第二次 `edit` 直接恢复结果。输出仍为 `deliverables/final-edited.mp4`，不会覆盖 `deliverables/final.mp4`。

旧 edit-plan v1 通过内存迁移继续读取和渲染：速度默认为 1.0，单镜头滤镜为空，全局滤镜、边界转场和 -16 LUFS 语义保持不变；原文件不会被静默重写。

## ChatCut 与剪映

ChatCut 只有在当前 Codex 任务真实暴露并授权相关工具时才能提交。CLI 交接包只表示“准备完成”，不表示用户已安装、登录或授权 ChatCut。真实适配必须返回远端项目 ID、渲染资产、输出 SHA-256 和未映射功能，再通过本技能的 MP4/QA 门禁。

本阶段任务没有 ChatCut 工具，因此稳定自动后端仍为原生 FFmpeg。剪映专业版的本机草稿 payload 仍是版本耦合的 opaque 数据，没有可验证的跨用户公开接口；`jianying-draft` 继续只输出媒体、重链接表和兼容性报告，明确 `actual_draft=false`，不会写入用户草稿目录。

## 升级

基础项目 schema 未强制升级。既有项目、DPAPI 凭据、安装档位、组件源码和模型缓存保持兼容。运行 `install.ps1 -Repair -Force` 后用 `version`、`install.ps1 -Check`、`doctor` 和 `editing-capabilities` 验证安装。
