# v2.4.0 ChatCut 适配器发布说明

v2.4 在 v2.3 的像素证据和 FFmpeg 编辑计划 v2 之上，接入已安装的 ChatCut Codex 插件边界。核心原则是：插件安装、OAuth 认证和当前任务可调用工具是三个不同状态；只有真实 MCP 工具可见时，才允许修改 ChatCut 项目。

## 已确认的插件状态

本机 ChatCut 插件目录为 `0.2.25`，清单包含 `chatcut` MCP server 和 hosted ChatCut 工作流。`codex mcp get chatcut` 显示 server 已启用，`codex mcp login chatcut` 可完成 OAuth。Python CLI 能可靠判断插件清单和 MCP 配置，但不能从独立进程读取当前任务的 `mcp__chatcut__*` 工具清单，因此不会把“已安装”报告成“可编辑”。

运行：

```powershell
python grok-video-studio/scripts/grok_video_studio.py chatcut-capabilities
```

如果当前任务仍没有 ChatCut 工具，执行 `codex mcp login chatcut` 后启动新的 Codex 会话。不要通过猜测 URL、数据库或插件缓存来替代 MCP 工具。

## 适配流程

1. 先执行 `edit-plan`、`edit-validate`，确认镜头窗口、速度、滤镜、边界转场、响度和干净母版路径。
2. 执行 `edit-handoff --backend chatcut`，生成 `deliverables/chatcut-handoff.json`。其中 `integration_contract` 包含源计划 SHA-256、源媒体清单、操作顺序、语义功能映射、必需工具和回执 schema。
3. ChatCut 工具可见时，按插件技能先 `list_projects`/`create_project`/`target_project`，再 `browse_assets`、`import_media`、`manage_timelines` 和 `edit_item`。本地源文件通过插件自带 `asset-import/scripts/upload-media.mjs` 上传；不先用 FFmpeg flatten 成单个视频。
4. 结构编辑完成后重新读取 `read_project`/`preview_timeline`，用时间线预览和 `render_cloud_screenshot` 检查裁切、速度、效果、转场、音频和画面。只在用户要求导出时调用 `submit_export` 并用 `track_export` 等待完成。
5. 将已下载的 MP4 放在项目目录内，写入回执后执行：

```powershell
python grok-video-studio/scripts/grok_video_studio.py chatcut-receipt-validate <project> <receipt.json> --confirm
```

接受条件：远端项目和时间线 ID 存在，输出是可读取 MP4，文件 SHA-256 与回执一致，源计划 SHA-256 未改变，结构和视觉复核均为 true，`tool_trace` 非空且能追溯 MCP 操作，`unmapped_features` 为空。接受后回执写入 `deliverables/chatcut-receipt.json`，并按回执哈希归档到 `deliverables/chatcut-receipts/`。

## edit-plan v2 映射边界

| 项目能力 | ChatCut 语义操作 | 通过什么确认 |
| --- | --- | --- |
| 镜头入出点、速度 | `edit_item` 时间线实例 | `preview_timeline`、`inspect_item` |
| 滤镜、转场、特效 | 先 `browse_library`，再 `edit_item` | 时间线结构和组成帧 |
| 音频混音、响度 | 只使用实时 schema 暴露的字段 | 时间线读取、导出后音频 QA |
| 干净母版 | 保留本地 `deliverables/final.mp4`，ChatCut 只承载可编辑副本 | 计划哈希和输出哈希 |

插件技能的具体参数以当前 MCP manifest 为准；合同只固定语义，不猜测隐藏字段。未映射能力必须回写到 `unmapped_features`，因此不会静默丢失滤镜、转场、音频或字幕。

## 回退与剪映边界

ChatCut 工具缺失、认证失效、导入被主机策略拒绝、时间线复核失败或回执不完整时，`auto` 使用原生 FFmpeg；不会声称 ChatCut 已完成。`edit-handoff --backend jianying-draft` 仍然只是媒体、计划、重链接表和兼容性报告，不生成伪造的通用剪映草稿。

- 新增适配器单元测试覆盖安装/任务工具状态分离、计划绑定、回执哈希、MP4/QA 和未映射拒绝。
- 现有视觉证据、编辑 v2、安装和跨平台测试继续作为发布门禁。
