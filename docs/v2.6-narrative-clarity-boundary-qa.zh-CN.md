# v2.6 叙事清晰度与镜头边界修复

本版本针对“看不懂在做什么、镜头拼接不连贯、每段末尾叹气或摆姿势”增加了三层门禁。

## 故事因果链

多镜头项目可以在 `project.json` 填写 `story_contract`：

```json
{
  "required": true,
  "goal": "角色必须在暴雨前卖掉桃子",
  "obstacle": "村民被更高报价吸引而拒绝交易",
  "decision": "村民选择等待更高价",
  "consequence": "暴雨后桃子吸水腐坏，交易窗口关闭",
  "payoff": "证据证明低价是为了提前承担天气风险"
}
```

每个 `story_beats` 应写 `visible_event`、`audience_effect` 和 `why_next`。`preflight` 会返回 `story.score`；显式 `required=true` 且低于 70 分时阻断付费生成。

## 两种声音模式

- `audio.mode=native-dialogue`：人物说话，逐句台词负责说话人、时间和口型审核。
- `audio.mode=narration`：上游生成画外旁白，人物必须闭嘴、无口型，字幕仍由 `subtitle_source` 独立控制。
- `audio.mode=local-narration`：画面只生成动作、环境声和无口型表演；本地 `dialogue-render` 使用 `audio.narrator_voice` 和 `shot.narration` 生成旁白音轨。

旁白项目默认建议 `subtitle_source=none`。需要字幕时使用 `project` 导出 SRT，不让视频模型把文字画进画面。

## 镜头边界

相邻镜头应分别填写 `exit_action`、`continuity_out`、下一镜 `entry_action` 和 `continuity_in`。中间镜头的 `exit_behavior` 使用 `continue-action` 或 `cut-on-action`，末镜才使用 `ending-hook`。

`quality.tail_auto_trim=true` 时，编辑计划和直接拼接会检测非末镜头的尾部静止区，自动缩短 `edit_out`，并在 `state.json.deliverables.final.boundary_qa` 记录原始和新的出点。自动裁切只处理非末镜头，最终钩子保留给人工审核。

## 验收清单

1. `preflight`：查看 `story.score`、音频模式和边界警告。
2. `qa --strict`：检查音轨、字幕像素、尾部运动、黑帧和冻结帧。
3. 打开 `deliverables/qa-frames`：人工确认出点仍在动作中，不是叹气、点头、挥手或摆姿势。
4. 审核后再 `assemble` 或 `edit`，并保留 `boundary_qa` 记录。
