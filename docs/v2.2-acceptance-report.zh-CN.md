# v2.2.0 发布验收报告

验收日期：2026-09-01。测试凭据只从当前用户的 Windows DPAPI 配置读取；报告、项目源码和测试代码均不保存 Key。`F:\AI视频数据库` 仅作为只读视觉参考，不复制、不索引进仓库，也不作为安装资源。

## 视觉分类证据

- 只读盘点数据库中 133 张图片和 58 条视频。目录名 `真人`、`动漫`、`动画` 存在视觉重叠，不能直接作为生成合同。
- `medium` 只描述渲染语言；主体来源另分为实际真人 `real-person`、AI 合成真人 `synthetic-human`、动漫/CG 类人虚构角色 `human-like-fictional`。
- 接近真人的动漫、三渲二和 CG 人物始终属于 `human-like-fictional`。通用“真人”描述只支持 `photoreal` 媒介判断，不足以证明实际人物身份。
- 自动分类只分析文本和引用文件名；低置信度、混合类型和未知主体来源必须人工或多模态复核后确认。

## 付费上游验收

| 用例 | 上游与请求 | 技术结果 | 视觉结果 | 结论 |
| --- | --- | --- | --- | --- |
| 初始 3D 动漫 I2V | QuickAI，1 图 + 1 视频 | 通过 | 拒绝 | 主体正确为虚构动漫角色，但整体偏平面 2D，暴露类型提示污染和 3D 约束不足 |
| 合成真人 T2V | QuickAI New，1 视频 | 通过 | 通过 | 光照、皮肤、脸部、双手、浇水壶接触和水流连续；类型为 `synthetic-human`，不是实际真人 |
| 修正后 3D 动漫 I2V | QuickAI，1 图 + 1 视频 | 通过 | 通过 | 建模体积、衣物和包体几何、投影、环境遮蔽、空间深度及运动连续；类型为 `3d-anime + human-like-fictional` |

共执行 2 次生图和 3 次视频创建，所有用例均设置单次上限且没有自动重试。轮询期间 QuickAI 曾在 `queued` 状态返回原始 `100%`；显示层正确限制为 `20%`，仅在任务完成后显示 `100%`。QuickAI 与 QuickAI New 都返回 848x480 源片，技能按合同组装为 1280x720、30 fps、H.264/yuv420p、AAC 48 kHz 双声道交付。

初始失败触发并验证以下修复：

- 移除动画提示中的 `photographic image` 和 `feature-film photography` 污染，按媒介生成 live-action、animation 或 motion-graphics 画面合同。
- 强化 `3d-anime` 的体积、建模几何、toon/PBR 材质、投影、环境遮蔽和禁止平面 2D 约束。
- QA 增加媒介匹配阻断项，技术转码成功不再等价于视觉通过。
- 进度显示保持单调，并限制排队/处理中错误的上游完成值。

## 原生剪辑验收

使用两条真实生成 MP4 执行本地两镜头时间线：`dissolve=0.35s`、`cinematic` 滤镜、保留源音频。输出 `deliverables/final-edited.mp4` 为 11.81 秒、1280x720、30 fps、H.264/AAC，技术 QA 无错误。转场前、中、后帧人工检查无黑帧、闪帧、尺寸跳变或异常叠层。

第二次执行命中计划和输入 SHA-256 签名，返回 `resumed=true`；`deliverables/final.mp4` 的哈希前后一致，证明编辑不会覆盖干净母版。

## 外部后端边界

- 当前任务没有 `mcp__chatcut__*` 工具，ChatCut 不被冒充为可用。CLI 输出带能力门禁、媒体哈希和必需回执字段的交接包；外层和内嵌计划的后端均为 `chatcut`。
- 本机只读检测到剪映专业版 11.2.0.14339，实际草稿内容是版本耦合的 opaque Base64-like payload。导出仅包含媒体副本、编辑计划、重链接表和兼容性报告，明确 `actual_draft=false`，不写用户草稿目录。
- 独立 CLI 的稳定自动后端是原生 FFmpeg。ChatCut 只在当前任务工具可见且获授权时使用；剪映交接只能由用户显式选择，不作为静默回退。
