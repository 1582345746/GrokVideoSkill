# v2.2.0 视觉类型与原生剪辑发布说明

v2.2 增加两项共用能力：多维视觉类型合同，以及生成完成后的可恢复剪辑合同。两者适用于 T2V、I2V、连续剧和新闻视频，不新增上游产品路线。

## 视觉类型

项目可自动或手动声明：

- `medium`：`photoreal`、`2d-anime`、`3d-anime`、`stylized-3d`、`motion-graphics`、`hybrid`。
- `subject`：人物、虚构角色、吉祥物、产品、环境或图形。
- `subject_nature`：有实际来源身份的真人 `real-person`、AI 合成真人 `synthetic-human`、动漫/CG 类人虚构角色 `human-like-fictional`、非人虚构角色、物体、环境、图形、混合或未知。
- `realism`、`identity_strictness`、`performance_complexity`。

`photoreal` 只表示外观接近摄影，不代表画面主体是真人。数据库中相似真人的动漫/CG 角色应记录为 `human-like-fictional`；由模型原创、但采用真人镜头语言的人物记录为 `synthetic-human`；只有实际人物照片、实拍素材或可确认的真人身份才使用 `real-person`。自动 CLI 只分析文本和文件名；实际图片或视频必须由 Codex/用户查看后确认。低置信度、混合媒介或主体真实性未知时，预检要求复核。

真人类 QA 除面部、肢体和身份稳定性外，还阻断手指与道具融合、抓握关系错误、液体运动断裂、布料穿模和不合理接触。技术转码通过不等于视觉验收通过。

## 剪辑

`edit-plan.json` 独立于 `project.json`，`edit-state.json` 记录计划和输入签名、分段进度、输出哈希与 QA。原生 FFmpeg 支持硬切、dissolve、fade-black、wipe-left、slide-left，以及电影感、冷暖、鲜艳、黑白、降噪和锐化滤镜。输出为 `deliverables/final-edited.mp4`，不会覆盖 `deliverables/final.mp4`。

```powershell
python grok-video-studio/scripts/grok_video_studio.py edit-plan <project> --transition dissolve --transition-seconds 0.25 --filter cinematic
python grok-video-studio/scripts/grok_video_studio.py edit-validate <project>
python grok-video-studio/scripts/grok_video_studio.py edit <project>
```

第二次执行相同计划会校验 SHA-256 并直接恢复，不调用任何生成上游。

## ChatCut 与剪映

ChatCut 仅在当前 Codex 任务加载并授权 `mcp__chatcut__*` 工具时可用。独立 Python CLI 无法枚举任务级 MCP 工具，因此 `auto` 的本地确定性后端是 FFmpeg。`edit-handoff --backend chatcut` 输出能力门禁、媒体清单和必须回传的渲染回执。

剪映专业版 11.2.0.14339 的本机只读实验显示，`draft_content.json` 与 `draft_meta_info.json` 是 opaque Base64-like payload，不是稳定公开 JSON。v2.2 的 `jianying-draft` 后端只输出媒体副本、edit-plan、relink map 和兼容性报告，并明确 `actual_draft=false`。它不会写入用户剪映草稿目录，也不是 ChatCut 缺失时的默认后端。

## 迁移

旧项目无需修改即可读取。需要持久化新字段时运行：

```powershell
python grok-video-studio/scripts/grok_video_studio.py migrate <project>
```

第一次迁移保存 `project.pre-v2.2.json`，随后补充缺失的视觉、布局和 prompt 字节字段。重复迁移无变化。

真实上游、视觉复核、原生剪辑、ChatCut 门禁和剪映边界的发布证据见 [v2.2 发布验收报告](v2.2-acceptance-report.zh-CN.md)。
